# Эмулятор командной оболочки

Вариант №28. Практическая работа №1 по дисциплине
«Конфигурационное управление», РТУ МИРЭА, ИКБО-40-25.

## Описание

GUI-эмулятор командной оболочки UNIX-подобной ОС на Python и Tkinter.
Эмулятор поддерживает диалог с пользователем, разбор аргументов
в кавычках, параметры запуска, стартовый скрипт и журнал вызовов
команд в формате XML.

Работа с виртуальной файловой системой (VFS) из ZIP-архива
появится на этапе 3; сейчас путь к VFS только запоминается
и определяет имя VFS в заголовке окна.

## Требования

- Python 3.10 или новее
- Tkinter (входит в стандартную поставку Python с python.org)

Сторонние библиотеки не используются.

## Структура проекта

| Путь | Назначение |
|------|------------|
| `src/main.py`   | точка входа: параметры, отладочный вывод, запуск |
| `src/config.py` | параметры командной строки и стартовый скрипт |
| `src/shell.py`  | ядро эмулятора: разбор строки и выполнение команд |
| `src/logger.py` | журнал вызовов команд в формате XML |
| `src/gui.py`    | графический интерфейс на Tkinter |
| `src/errors.py` | исключения эмулятора |
| `tests/`        | модульные тесты |
| `examples/`     | стартовые скрипты эмулятора |
| `scripts/`      | скрипты ОС для проверки параметров запуска |

Ядро (`shell.py`) не зависит от интерфейса, поэтому тестируется
без запуска окна.

## Запуск

    ./run.sh [--vfs PATH] [--log PATH] [--script PATH]

### Параметры командной строки

| Параметр | Описание |
|----------|----------|
| `--vfs PATH`    | путь к физическому расположению VFS; имя файла без расширения становится именем VFS |
| `--log PATH`    | путь к XML-файлу журнала вызовов команд |
| `--script PATH` | путь к стартовому скрипту |
| `-h`, `--help`  | справка по параметрам |

Все параметры необязательны. При запуске эмулятор выводит
в терминал все параметры (отладочный вывод):

    [debug] параметры запуска эмулятора:
    [debug]   vfs_path = images/demo.zip
    [debug]   vfs_name = demo
    [debug]   log_path = logs/session.xml
    [debug]   script_path = (не задан)

Путь к VFS на этапе 2 только запоминается и не проверяется.
Путь к журналу проверяется при запуске:

- путь должен вести к файлу, а не к каталогу;
- расширение файла — `.xml`;
- каталог, в котором лежит файл, должен существовать;
- если файл уже есть, он должен быть журналом эмулятора
  (корректный XML с корневым элементом `<log>`).

Ошибка в параметрах (нет файла скрипта, неверный путь к журналу,
пустой путь) выводится в терминал, окно не открывается,
код завершения — 1. Неизвестный параметр — код 2.

## Команды эмулятора

| Команда | Описание |
|---------|----------|
| `ls [args]`  | заглушка: выводит своё имя и аргументы |
| `cd [args]`  | заглушка: выводит своё имя и аргументы |
| `conf-dump`  | выводит параметры эмулятора в формате «ключ = значение» |
| `exit`       | завершает работу эмулятора |

Команды `exit` и `conf-dump` не принимают аргументов.

### Разбор строки ввода

Слова разделяются пробелами. Двойные кавычки группируют текст
с пробелами и в результат не попадают; кавычки могут стоять
в середине слова.

| Ввод | Команда и аргументы |
|------|---------------------|
| `cd "my folder"` | `cd`, `my folder` |
| `cd ""`          | `cd`, пустая строка |
| `cd a"b c"d`     | `cd`, `ab cd` |
| `cd "abc`        | ошибка: незакрытая кавычка |

Ошибки ввода выводятся в окно и не прерывают работу эмулятора.

## Стартовый скрипт

Текстовый файл с командами эмулятора, по одной на строку.
Пустые строки и строки, начинающиеся с `#`, пропускаются.

Команды выполняются последовательно; на экране отображаются
и ввод, и вывод, как при ручной работе. Ошибочная строка выводит
сообщение и пропускается. Команда `exit` завершает скрипт
и работу эмулятора.

Примеры — в каталоге `examples/`:

| Файл | Содержание |
|------|------------|
| `start_demo.txt`   | все команды и режимы разбора |
| `start_errors.txt` | ошибочные строки вперемешку с корректными |
| `start_exit.txt`   | завершение работы из скрипта |

## Журнал команд

Каждый вызов команды записывается в XML-файл. Если файл уже
существует, события дописываются в конец.

```xml
<?xml version='1.0' encoding='utf-8'?>
<log>
  <event>
    <user>julia</user>
    <datetime>2026-09-24T12:30:05</datetime>
    <input>cd "my folder"</input>
    <command>cd</command>
    <arg>my folder</arg>
    <status>ok</status>
  </event>
  <event>
    <user>julia</user>
    <datetime>2026-09-24T12:30:09</datetime>
    <input>wat</input>
    <command>wat</command>
    <status>error</status>
    <message>wat: команда не найдена</message>
  </event>
</log>
```

## Примеры использования

Запуск с журналом (каталог для журнала должен существовать):

    mkdir -p logs
    ./run.sh --vfs images/demo.zip --log logs/session.xml

Сеанс в окне эмулятора:

    demo$ cd "my folder"
    cd: аргументы: 'my folder'
    demo$ cd a"b c"d
    cd: аргументы: 'ab cd'
    demo$ wat
    ошибка: wat: команда не найдена
    demo$ cd "abc
    ошибка: незакрытая кавычка в строке ввода
    demo$ conf-dump
    vfs_path = images/demo.zip
    vfs_name = demo
    log_path = logs/session.xml
    script_path = (не задан)
    demo$ exit
    Завершение работы эмулятора.

Запуск со стартовым скриптом:

    ./run.sh --script examples/start_demo.txt

## Сборка и тесты

Сборка не требуется: Python — интерпретируемый язык,
сторонние библиотеки не используются.

Модульные тесты:

    python3 -m unittest discover tests

Скрипты ОС для проверки параметров запуска:

| Скрипт | Что проверяет |
|--------|---------------|
| `scripts/test_defaults.sh`   | запуск без параметров |
| `scripts/test_each_param.sh` | каждый параметр по отдельности |
| `scripts/test_all_params.sh` | все параметры вместе, дозапись журнала |
| `scripts/test_errors.sh`     | ошибки в параметрах запуска |

Журналы тестовых скриптов пишутся в каталог `logs/`,
который не попадает в репозиторий.
